One request through a rate limiter

Goal: trace how your booking API can allow up to 20 email-verification requests per IP in any one-hour window.

Open the compact reference sheet →

1. Put a gate before the handler

An HTTP handler is something with a ServeHTTP(w, r) method. A middleware wraps a handler: it can respond immediately or pass the same request to the next handler. Go's handler documentation

Incoming request → limiter checks IP + window → 429 if full, otherwise → email-verification handler

// Sketch: allow is a separate function you will implement.
func limit(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        if !allow(r) {
            http.Error(w, "too many requests", http.StatusTooManyRequests)
            return
        }
        next.ServeHTTP(w, r)
    })
}

The return matters: a blocked request must stop before reaching the verification handler.

2. Identify the caller

For an incoming server request, r.RemoteAddr normally contains the direct peer's address and port, for example 192.0.2.10:54321. Use net.SplitHostPort to obtain the host; it handles bracketed IPv6 too. Handle an invalid address as an error instead of accidentally putting unrelated callers into one empty bucket. Request documentation

The direct peer may be a proxy, and many customers can share an IP. Forwarded headers are client-controlled unless a trusted proxy is configured. One IP is therefore a useful limit key, not proof of a person's identity.

3. Count the previous hour

Imagine map[string][]time.Time: each IP maps to the times of its accepted requests. Capture now, discard timestamps at or before now.Add(-time.Hour), then check how many remain. With 19, append this request and allow it. With 20, reject it. At exactly one hour old, a timestamp is outside this window.

Try it. At 11:00, an IP has 20 accepted requests since 10:01. What happens to the next request?

4. Make the check safe under concurrency

Go can serve multiple requests at once. If two requests both see 19 entries and both append, the limit can be exceeded. Put pruning, counting, and appending inside one sync.Mutex lock. Release it before invoking the next handler, so a slow email-verification request doesn't hold the limiter lock. Go's mutex documentation

Try it. After the check allows a request, what should happen before calling the next handler?

5. Test without waiting an hour

Give the limiter a clock function, such as now func() time.Time. Production uses time.Now; a test uses a controlled time and advances it. httptest can send a request to the middleware and capture its response. Check the 20th and 21st requests, another IP, the exact hour boundary, and concurrent requests; use Go's race detector for the concurrent case.

Lifecycle: remove inactive IP entries as well as old timestamps, or one-off IPs will accumulate in memory. An in-memory limit resets on restart and applies separately to each API instance.
